# DocProof — Windows 文档纠错工具

基于 DeepSeek V4 大模型 + 讯飞 OCR 的中文文档（公文/年鉴）校对工具。
**架构：本地 HTTP 服务器 + 浏览器客户端**——服务端跑在 Windows 上，用户用任意
现代浏览器访问即可上传文档、查看错误、采纳修正、导出结果。

支持错别字、语法语病、标点误用、数据/逻辑矛盾四类问题的自动检出，并提供
**滑动式分页校对**、**跨页上下文核对**、**二次复核机制**降低误报、
**自定义校对规则**、**置信度分级**等能力，最终可在原文格式（docx 加粗等）上
直接替换并导出。

## 版本

**服务端 v1.3**（2026-07-31）

### v1.3 更新内容

- **多用户隔离（重要）**：从单机单用户升级为多用户 token 鉴权体系。每个用户持有
  独立 `access_token`，会话按 `user_id` 绑定，A 用户无法访问 B 用户的会话、文档、
  修正记录。详见下文「多用户与安全」。
- **凭据加密升级**：`access_token` 落盘存 **SHA-256 hash**（不可逆），文件泄露也
  无法还原 token 原文；per-user overrides 中的敏感字段（LLM/讯飞密钥）改用 **DPAPI
  加密**，与全局配置策略一致。
- **首启自动创建管理员**：首次启动若无任何用户，自动创建管理员账户并在控制台
  **一次性**打印其 token（后续不再显示，磁盘上只留 hash），用此 token 登录后可在
  「用户管理」中创建其他用户、重置 token、切换管理员状态。
- **per-user 配置覆盖**：普通用户可在「设置」中填写自己的 LLM API Key / 模型 /
  Base URL 等覆盖全局默认；留空则继承全局。管理员写全局配置。
- **限流**：单用户最多 2 个并发纠错任务 + 每分钟 120 次 API 请求（滑动窗口），
  超限返回 429，防止单用户耗尽资源。
- **SSRF 防护**：当已配置 LLM API Key 时，禁止 `llm_base_url` 指向内网/回环地址
  （防止服务器把带密钥的请求发到内网）；未配置 Key 的本机调试场景放行。
- **配置原子写**：`config.py` 与 `users.py` 均改为临时文件 + `os.replace` 原子写，
  并发写不会损坏配置文件。
- **默认监听 127.0.0.1**：从 v1.1 的 `0.0.0.0` 改回 `127.0.0.1`（多用户场景下
  默认仅本机访问更安全）；如需局域网访问显式加 `--host 0.0.0.0`。
- **新增 API**：`/api/login`、`/api/me`、`/api/users`（增删改查，仅管理员）、
  `/api/users/<id>/{reset,admin,rename}`。

### v1.2 更新内容

- **前端高亮错位修复（重要）**：此前 `renderPage()` 先对整页 `escapeHtml` 再用基于原文的
  `offset_start/offset_end` 去 slice，导致原文含 `&`/`<`/`>`/`"`/`'` 时文本被拉长、
  offset 指向错误位置，错误高亮跑到无关文本上。**该问题仅出现在 mx.docx 等含特殊字符
  的文档**，其他文档不含这类字符故未触发。改为在原文上按偏移切分后再分段 escapeHtml，
  offset 始终基于原文，不再失效。
- **定位日志提升到 INFO**：`_find_in_text` 各级匹配（精确/标点归一化/前缀/去空白/子串）
  均输出 `定位[1-精确] cand=... → idx=...` 追踪信息，无需开 debug 即可看到定位过程，
  便于排查错位问题。
- **最长子串回退收紧**：取消全文回退（仅从 consumed 之后查找），子串长度下限从 6 字
  提升至 8 字，长度阈值从 60% 提高到 75%，避免短子串在无关位置误命中。
- **精确匹配优先 consumed 之后**：先从 `start_from` 起查找，找不到时才全文回退且需满足
  `idx≥start_from`，减少重复短语被错误消耗。

## 功能特性

- **多格式输入**：docx / txt / 文字版 PDF 直接提取；图片与扫描版 PDF 走讯飞 OCR。
- **浏览器客户端**：HTML 单页应用，服务端启动后用浏览器打开访问 URL 即可使用，
  无需安装任何客户端运行时；支持文件拖放上传、错误高亮预览、实时进度显示。
- **滑动式分页校对**：文档按页处理，校对完一页确认后再翻下一页，避免一次性消耗过多 token。
- **跨页上下文核对**：校对当前页时，模型可同时看到上一页结尾与本页开头，以及本页结尾与下一页开头，
  便于发现跨页的年份/数据/人名不一致。
- **AI 校对**：按页分块调用 LLM，NDJSON 流式实时推送"正在分析第 N 块…累计 Xs"，避免误以为卡住。
- **二次复核**（可开关）：对每块检出的错误再做一轮交叉核对，重点排查年份/数据/人名/地名
  一致性——例如前文均为 2025 年，模型却称"此处应为 2024 年"，复核会将其标为存疑或疑似误报。
- **置信度分级**：每条错误标注「明确」或「存疑」；存疑行整行标灰，可按置信筛选，明确条目优先排列。
- **自定义规则**：5 个预置开关（数字与汉字空格、全半角标点等，默认全关不报）+ 自定义规则文本框。
- **OCR 图片识别纠错模式**：工具栏一键切换，专用提示词覆盖形近字误识、数字误识、标点误识、
  漏字漏行、重复识别、乱码字符、残句拼接等 8 类 OCR 常见错误。
- **格式保留导出**：txt→txt；docx→docx（只改文字，保留加粗等原格式）；PDF/图片→修正后的 docx。
  导出文件由浏览器直接下载到本机下载目录。

## 运行

### 1. 安装依赖

```powershell
# 首次：创建虚拟环境并安装依赖（已装过可跳过）
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

`requirements.txt` 仅含三项：`python-docx` / `PyMuPDF` / `requests`。
不再依赖任何 GUI 框架（PySide6 已移除），客户端由浏览器渲染。

### 2. 设置监听端口

服务端启动前支持三种方式指定端口（按优先级）：

1. **命令行参数**：`--port` / `-p`
   ```powershell
   .venv\Scripts\python main_server.py --port 8080
   ```
2. **环境变量**：`DOCPROOF_PORT`
   ```powershell
   $env:DOCPROOF_PORT = "8080"
   .venv\Scripts\python main_server.py
   ```
3. **交互输入**：不加任何参数启动时，控制台会提示输入端口，回车确认默认 8000
   ```powershell
   .venv\Scripts\python main_server.py
   # ============================================================
   # DocProof 服务器启动 - 端口设置
   # ============================================================
   # 请输入监听端口 [默认 8000，回车确认]:
   ```

启动后控制台会打印访问 URL 便于直接打开：

```
============================================================
DocProof 服务器已启动（多用户隔离版 v1.3）
  监听地址:    127.0.0.1:8000
  浏览器访问:  http://127.0.0.1:8000/
  健康检查:    http://127.0.0.1:8000/api/health
  全局配置:    C:\Users\<你>\AppData\Roaming\DocProof\_server_config.json
  用户数据:    C:\Users\<你>\biaoshifu\_users.json
  敏感字段:    DPAPI 加密（绑定当前 Windows 用户）

  ⚠ 首次启动：已自动创建管理员账户
    管理员 token（仅显示一次，请妥善保存）：
    <一长串 URL 安全 token>
    在浏览器打开访问 URL，粘贴此 token 登录。
    登录后可在「用户管理」中创建其他用户、重置 token。
============================================================
```

> 首次启动的控制台 token **只显示一次**，关闭窗口前务必保存。若丢失，删除
> `~\biaoshifu\_users.json`（无该目录时在 `%APPDATA%\DocProof\users\_users.json`）后
> 重启服务端即可重新走「首启创建管理员」流程
> （会丢失已建的其他用户，需重建）。

> 默认监听 `127.0.0.1`（仅本机访问）。如需局域网其他设备访问，加 `--host 0.0.0.0`，
> 并用 `http://<本机IP>:<端口>/` 访问；此时控制台会额外提示
> 「局域网内任何设备都能访问，请确保 token 不外泄」。

### 3. 浏览器访问

启动服务端后，在浏览器打开控制台输出的 URL 即可使用客户端。建议使用 Chrome / Edge /
Firefox 等现代浏览器。客户端功能：

- **登录**：首次打开会显示登录遮罩，粘贴 access token 后登录。token 存在浏览器
  `localStorage`，关闭后下次打开自动登录；点右上角 ⏏ 可退出。
- **拖放上传**：把 docx/txt/pdf/图片直接拖到上传区，或点击选择文件。
- **文档预览**：左侧按页显示文档原文，错误位置高亮标注。
- **错误列表**：右侧按未确认/已确认双标签展示，可按错误类型、置信度、页码筛选。
- **采纳/忽略/撤回**：每条错误可单独采纳（自动应用修正到文本）、忽略或撤回。
- **一键采纳**：把当前筛选出的所有错误一次性全部采纳。
- **实时进度**：纠错过程中底部控制台滚动显示状态、块号、token 用量；进度条实时更新。
- **设置对话框**：在浏览器里填写 LLM 凭据、讯飞 OCR 凭据、模型选择、校对规则等，
  敏感字段通过 HTTPS 等价路径加密落盘（详见下文"配置与安全"）。
- **用户管理**（仅管理员）：工具栏 👥 按钮打开用户管理对话框，可新增用户并
  查看其 token、重置 token、重命名、切换管理员状态、删除用户。
- **导出**：点击导出按钮，浏览器自动下载修正后的文件。

## 配置与安全

### 配置文件位置

服务端配置文件位于用户级目录，**不与源代码同目录**，避免误打包或随源码泄露：

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\DocProof\_server_config.json` |
| 其他 | `~/.config/docproof/_server_config.json` |

首次启动时若目录不存在会自动创建。

### 敏感字段 DPAPI 加密

配置文件中以下字段在落盘时使用 **Windows DPAPI** 加密，密文绑定当前 Windows 用户账户，
**换电脑、换用户、复制到其他位置均无法解密**：

- `llm_api_key`（LLM API Key）
- `xf_appid`（讯飞 APPID）
- `xf_api_key`（讯飞 API Key）
- `xf_api_secret`（讯飞 APISecret）

加密格式：`"DPAPI:<base64 密文>"`。运行时读出后自动解密供服务端使用；
浏览器客户端永远不会拿到密钥原文（`/api/config` 仅返回非敏感配置）。

### 旧版明文配置迁移

若项目中存在旧版明文 `config.json`，首次启动新服务端会**一次性迁移**：
读取旧明文 → 加密敏感字段 → 写入新路径 `%APPDATA%\DocProof\_server_config.json`。
迁移完成后旧 `config.json` 不会被自动删除（避免误删），可由用户自行清理。

### 凭据更新

浏览器「设置」对话框中填入新凭据后，通过 `POST /api/credentials` 单独提交，
服务端调用 DPAPI 加密后落盘。留空字段视为"保持不变"。

## 多用户与安全

v1.3 起引入多用户体系。设计目标：单端口承载多用户，会话与文档彼此隔离，
单用户无法耗尽服务器资源，密钥不被服务器发往内网。

### 用户数据文件

| 文件 | 字段 | 加密 |
|---|---|---|
| `_users.json` | `access_token` | **SHA-256 hash**（不可逆） |
| `_users.json` | `overrides.llm_api_key` / `xf_*` 等敏感字段 | **DPAPI 加密**（绑定 Windows 用户） |
| `_users.json` | `display_name` / `is_admin` / `created_at` / 非敏感 overrides | 明文 |
| `_server_config.json` | 全局 `llm_api_key` / `xf_*` | **DPAPI 加密** |
| `_server_config.json` | 模型、规则、复核开关等 | 明文 |

> **分层加密策略**：服务端需要明文调用的密钥（LLM/讯飞）用 DPAPI 可逆加密；
> 服务端只需比对、不需要还原的凭据（access_token）用 SHA-256 hash 不可逆存储。
> 这样即使 `_users.json` 被完整盗走，攻击者既无法还原任何 token，也无法解密
> overrides 里的密钥（DPAPI 绑定 Windows 用户，换机不可解）。

### 鉴权流程

1. 客户端请求任意受保护接口时带 `Authorization: Bearer <token>`。
2. 服务端对输入 token 做 SHA-256，与 `_users.json` 中存储的 hash 用
   `secrets.compare_digest` 常时比较，命中则放行。token 原文绝不落盘。
3. 每个请求都会记录到该用户的限流计数器。
4. 导出下载链接因浏览器无法带 Header，支持 `?token=<token>` 兜底。

### 会话隔离

每个会话在创建时绑定 `user_id`，查询/预览/导出时均校验 `session.user_id == 当前用户 user_id`，
不匹配返回 404（不返回 403，避免泄露"会话存在但非本人"的信息）。

### 限流

| 维度 | 上限 | 触发后 |
|---|---|---|
| 单用户并发纠错任务 | 2 个 | 返回 429，提示「并发纠错任务过多」 |
| 单用户每分钟 API 请求 | 120 次 | 返回 429，提示「请求过于频繁」 |

限流状态存在内存（`_rate_state` 字典），服务重启后清零。120 次/分钟对正常使用
绰绰有余（纠错一个 30 页文档约 30-60 次 API 调用），但能挡住脚本滥用。

### SSRF 防护

`llm_base_url` 在保存时校验：

- 必须 `http://` 或 `https://` 开头。
- host 不能是内网/回环地址（`ip.is_private / is_loopback / is_link_local / ...`），
  域名 `localhost` 系列也视为内网。
- **特例**：当全局未配置 LLM API Key 时，允许指向内网（本机调试场景，无密钥可泄露）；
  已配置 Key 时一律拒绝，防止服务器把带密钥的请求发到内网伪造端点。

### per-user 配置覆盖

普通用户在「设置」中填写的字段写入自己的 `overrides`，运行时通过
`resolve_user_config()` 与全局配置浅合并：

- 非敏感字段（模型/Base URL/规则等）：直接覆盖。
- 敏感字段（API Key 等）：覆盖；填空字符串视为「清空自己的覆盖、回退全局」。
- 管理员的「设置」直接写全局配置（不进 overrides）。

### 管理员保护

- 首启无任何用户时自动创建管理员（user_id 固定为 `admin`），token 原文仅在控制台
  显示一次，磁盘上只存 SHA-256 hash，无法事后读取。
- **token 丢失恢复**：删除用户数据文件 `_users.json`（默认 `~\biaoshifu\_users.json`）
  后重启服务端，会重新走
  首启流程创建管理员（会丢失已建的其他用户，需重建）。
- 删除用户的接口会拒绝「删掉最后一个管理员」，避免锁死。
- 管理员可重置任意用户 token（旧 token 立即失效）、切换管理员状态、重命名、删除。

## API 一览

除标注「公开」外，所有接口都需 `Authorization: Bearer <access_token>` 头。
导出下载链接因浏览器无法带 Header，支持 `?token=<token>` 兜底。

| 方法 | 路径 | 鉴权 | 用途 |
|---|---|---|---|
| GET | `/` | 公开 | 浏览器客户端 `_index.html` |
| GET | `/api/health` | 公开 | 健康检查：模型、是否已配置密钥、是否开启鉴权 |
| POST | `/api/login` | 公开 | 用 token 换取用户信息（不含 token 本身） |
| GET | `/api/me` | 用户 | 返回当前登录用户信息 |
| GET | `/api/config` | 用户 | 返回当前用户合并后的非敏感配置（**密钥不返回**） |
| POST | `/api/config` | 用户 | 保存非敏感配置（管理员写全局，普通用户写自己的 overrides） |
| POST | `/api/credentials` | 用户 | 设置/更新敏感凭据（同上分流；DPAPI 加密落盘） |
| POST | `/api/upload` | 用户 | multipart 文件上传，返回 session_id + 页文本 |
| POST | `/api/proofread` | 用户 | NDJSON 流式纠错（按用户限流，最多 2 个并发） |
| GET | `/api/session/<id>` | 用户 | 查询会话状态与页文本（校验归属，他人会话返回 404） |
| POST | `/api/session/<id>/preview` | 用户 | 应用修正后返回页文本预览（校验归属） |
| POST | `/api/export` | 用户 | 应用修正后导出文件下载（校验归属） |
| GET | `/api/users` | 管理员 | 列出所有用户（不含 access_token 字段） |
| POST | `/api/users` | 管理员 | 新增用户，返回 user_id + access_token |
| DELETE | `/api/users/<id>` | 管理员 | 删除用户（最后一个管理员拒绝删除，避免锁死） |
| POST | `/api/users/<id>/reset` | 管理员 | 重置用户 token，返回新 token |
| POST | `/api/users/<id>/admin` | 管理员 | 切换管理员状态 |
| POST | `/api/users/<id>/rename` | 管理员 | 重命名用户 |

错误响应：

| 状态码 | 含义 |
|---|---|
| 401 | 缺少/无效 token |
| 403 | 需要管理员权限 |
| 404 | 会话不存在或非本人所有 / 路径未知 |
| 429 | 限流：每分钟请求超限 或 并发纠错任务超限 |

会话有 2 小时 TTL，超时未访问自动清理临时文件。

## 设置

浏览器「设置」对话框包含三个分区：

1. **LLM 服务商**：API Key、Base URL、模型选择。
   - 预置 DeepSeek / OpenAI / 自定义（OpenAI 兼容）。
   - DeepSeek 推荐 `deepseek-v4-flash`（非思考，快）和 `deepseek-v4-pro`（思考模式，更强）。
   - 旧名 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 停用，请使用 V4 命名。
2. **校对规则**：5 个预置开关（默认全关）+ 自定义规则文本框。
3. **高级**：Token 上限（默认 100 万，超限熔断）、二次复核开关与前后文摘要字数。
4. **讯飞 OCR**：APPID / APIKey / APISecret（用于图片和扫描版 PDF）。

## 模型选择与成本估算

### 两个模型怎么选

| 模型 | 模式 | 适合场景 | 并发上限 |
|---|---|---|---|
| `deepseek-v4-flash` | 非思考（默认） | **日常校对首选**：错别字、标点、明显语病、事实/数据矛盾 | 2500 |
| `deepseek-v4-pro` | 思考模式 | 严格审稿：标点方向、成分残缺等细微语法问题（**误报率更高**） | 500 |

> 旧名 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 停用，分别对应 flash 的非思考/思考模式。

**实测结论**（基于 24 个冲突文档数据集 + 5 篇隐蔽错别字文档）：
- **事实类错误**（数据/史实/年代）flash 检出率不输 pro，pro 在部分案例上反而漏报。
- **争议/体例类文档** pro 误报率显著高于 flash（12 条 vs 3 条）。pro 的思考模式倾向"主动挑问题"。
- **错别字**：同音字两者都能 100% 检出。
- **推荐**：默认用 flash；仅在需要细抓标点/语法细节时切 pro，并人工复核存疑项。

## 使用流程

1. **启动服务端**：`python main_server.py`（按提示设置端口或用 `--port`）。
2. **保存管理员 token**：首次启动控制台会一次性打印管理员 token，立即复制保存。
3. **浏览器访问**：打开控制台输出的 URL，粘贴管理员 token 登录。
4. **首次配置**：点客户端右上角「设置」，填写 LLM API Key（必填）和讯飞 OCR 凭据（仅图片/PDF 需要），保存。
5. **创建其他用户**（可选）：点工具栏 👥「用户管理」→ 新增用户，把返回的 token
   分发给使用者；普通用户登录后可在自己的「设置」里填覆盖配置。
6. **上传文件**：拖放或点击上传区选择文件。
7. **开始纠错**：点工具栏「开始纠错」，对当前页跑校对；底部控制台实时滚动状态与进度。
8. **处理错误**：右侧错误列表逐条采纳/忽略，或用过滤器筛选后一键采纳；左侧预览同步高亮。
9. **翻页继续**：「上一页 / 下一页」切换页码，可对每页分别跑纠错；翻页时有未确认错误会提示。
10. **导出**：点「导出」浏览器自动下载修正后的文件（txt/docx）。

## 项目结构

```
docproof_server/
├── main_server.py          # 服务端入口：HTTP 路由 + 鉴权中间件 + 会话管理 + 端口设置
├── _index.html             # 浏览器客户端（登录/上传/预览/错误/采纳/导出/设置/用户管理）
├── config.py               # 全局配置管理（DPAPI 加密、原子写、规则、复核开关、密钥 bootstrap）
├── users.py                # 多用户管理（token 鉴权、用户 CRUD、per-user overrides、限流）
├── requirements.txt        # 依赖：python-docx / PyMuPDF / requests
├── core/
│   ├── deepseek.py         # OpenAI 兼容 LLM 客户端
│   ├── docload.py          # docx/txt/PDF 文本提取与分页
│   ├── ocr_xfyun.py        # 讯飞 OCR（图片/扫描版 PDF）
│   ├── proofread.py        # 校对主逻辑：分块、跨页上下文、定位、规则过滤、二次复核
│   ├── exporter.py         # 格式保留导出（txt / docx 原位改写 / PDF→docx）
│   ├── progress.py         # 进度持久化（保留以兼容旧调用，浏览器版未使用）
│   └── models.py           # 数据模型（Page / ErrorItem / TokenUsage 等）
└── 1.ico                   # 图标
```

> 配置与用户数据均不在项目目录，避免误打包：全局配置在 `%APPDATA%\DocProof\` 下
> （`_server_config.json`）；用户数据默认在 `~\biaoshifu\` 下（`_users.json` /
> `_sessions.json`），该目录不存在时自动改用 `%APPDATA%\DocProof\users\`。

## 打包

如需把服务端打包成单文件 exe 分发：

```powershell
.venv\Scripts\pip install pyinstaller
.venv\Scripts\pyinstaller --onefile --name 文档纠错器-服务器 ^
    --icon 1.ico ^
    main_server.py _index.html config.py users.py core\*.py
```

- 产物：`dist\文档纠错器-服务器.exe`
- **安全**：`_server_config.json` 与 `_users.json`（含密钥密文 / token）绝不打包进 exe，
  运行时按用户写入 `%APPDATA%\DocProof\`
- 首次运行控制台会打印管理员 token；之后在浏览器「设置」里填写 LLM / 讯飞密钥
- 配置文件按 Windows 用户隔离，多 Windows 用户共用同一 exe 时各自独立
